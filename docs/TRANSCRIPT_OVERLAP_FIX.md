# 串流交界重複文字修正

使用者提供的最終 transcript 本身已有重複文字，因此無法把全部問題歸因於游標注入。未保存原始音訊與各視窗辨識結果，不能確認範例中的每個重複詞各自由哪一層產生。

這次修正 `TranscriptAccumulator.appendSlidingWindow`：

- 相鄰音訊視窗重疊時，以舊視窗尾端對齊新視窗開頭。
- 忽略空白、大小寫與句子標點差異，比對至少四個正規化字元後才採用寬鬆比對；保留原始輸出文字。
- 保留 C++、C#、路徑及版本號內部的技術標點。
- 移除任意內部共同字串對齊，避免只找到 Container 或 Kafka 就刪除無關內容、重播新視窗的前綴。
- Whisper 傳入視窗結束樣本位置；不重疊的音訊不做跨視窗去重。
- 不刪除單一視窗內的重複詞，保留使用者的自然重複與強調。

CLI 100 個 assertion 通過，包含 10 組合併、游標狀態與重複快照案例。另補 XCTest 回歸案例；本機 XCTest module 缺失限制仍存在。

此修正未加入語意改寫、全句去重或額外等待，因此不增加辨識輪詢間隔。沒有量測實際錄音重複率下降百分比。辨識模型在單次輸出就產生的重複／錯詞，以及沒有可靠共同邊界的不同辨識結果，仍可能留下重複內容；不宣稱完全消除。
